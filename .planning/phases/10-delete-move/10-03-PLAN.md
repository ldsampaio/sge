# Plan 10-03: imap_outbox (M7) + pre-sweep replay + delete/move/expunge commands

## Overview

- **Goal:** Durable `imap_outbox` queue (M7) with UIDVALIDITY-gated pre-sweep replay, optimistic local state + undo window, FTS/attachment cleanup, `SyncSummary` counters, and the three Tauri commands — offline delete/move survives reconnect and never resurrects same-pass.
- **Mode:** mvp
- **Deps:** 10-02 (manager lease methods, `MoveOutcome`, Trash detect). 10-01 verbs assumed.
- **Requirements:** DEL-01, DEL-02, MOVE-01 (backend-complete; UI wires in 10-04).

Reuse `ReplaySummary` + `moved` count.

## <threat_model>

- **Scope:** ASVS L1. First plan where queued destructive ops replay automatically — stale-replay is the catastrophic case.
- **Hazards:**
  - *Stale-UID delete after UIDVALIDITY renumber (wrong-message deletion):* mitigated by epoch stored at enqueue + whole-mailbox drop on mismatch before any STORE; `delete_missing_uids` also drops queue. Test: epoch-bump drops queue with zero verb calls.
  - *Same-pass resurrection (sweep re-inserts locally-deleted mail):* mitigated by pre-sweep `imap_outbox` replay (non-negotiable order) + convergence gate on both queues; test: offline-delete → sync pass → row stays hidden.
  - *`flag_outbox` contract break:* mitigated by untouched-table rule + flag-drop test; block on any migration altering `flag_outbox`.
  - *Orphan attachment dirs / FTS ghosts after expunge:* mitigated by best-effort dir removal + FTS trigger test; fs errors logged, never fail sync.
  - *Double-delete via `UNIQUE` race:* latest-wins upsert keeps one row per (mailbox,uid).
- **Block on high:** any replay path issuing STORE/MOVE before the epoch check, sweep running before `imap_outbox` replay, or `flag_outbox` schema alteration → block.
</threat_model>
