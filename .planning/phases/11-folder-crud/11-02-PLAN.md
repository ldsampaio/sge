# Plan 11-02: RENAME + DELETE — verbs, cache ops, commands, live gates

## Overview

- **Goal:** Rename and delete folders work against the real server with cache consistency: RENAME preserves UIDs and migrates selection atomically; DELETE refuses INBOX/`\Noselect`/children/non-empty-unconfirmed, cascades local cache, and falls back to INBOX.
- **Mode:** mvp
- **Deps:** 11-01 (`validate_leaf` reuse for rename leaf, `create_folder`/`list_mailboxes` refresh body, `FolderTreeResult` shape).
- **Requirements:** FOLD-05 (rename slice), FOLD-06 (delete slice).

## Wave 2: Transport + store + commands (blocked on 11-01)

Objective: rename/delete verbs, cache migrations, and guarded commands — UI affordances arrive in 11-03, but every command is callable and live-verified here.

## <threat_model>

- **Scope:** ASVS L1. First destructive folder verbs; wrong-target RENAME/DELETE is the catastrophic case.
- **Hazards:**
  - T-11-04 *Stale-selection use-after-rename (ops issued against the old name):* mitigated by returning `{old, new}` so the UI migrates in the same tick + `Refused`-class guards evaluated on fresh cached tree; test asserts zero verb calls on every refusal path. Block on high: any refusal path that still issues a verb.
  - T-11-05 *Subtree orphan on rename (`Pai` renamed, `Pai/Sub` left pointing at a dead prefix):* mitigated by prefix UPDATEs per delimiter + `Pai2` non-match test (LIKE-escape). Block on high: exact-row-only UPDATE.
  - T-11-06 *Silent data loss on non-empty delete:* mitigated by count guard + typed-name double confirmation + server-error mapping; empty-then-delete is never automated. Block on high: any DELETE issued without `confirmed + typed match` on a non-empty folder, or any automatic emptying.
- **Block on high:** refusal-path verb calls, exact-only rename UPDATE, unconfirmed non-empty DELETE → block.
</threat_model>
