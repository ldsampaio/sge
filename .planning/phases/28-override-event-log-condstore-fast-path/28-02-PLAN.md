2. After successful SELECT (Step 2), before UID SEARCH ALL (Step 3):
   - If CONDSTORE enabled AND highest_modseq != NULL (from queries::get_highest_modseq):
     a. Call `session.select_condstore().await` — if returns true:
        - Call `session.condstore_fetch_changedsince(range, highest_modseq).await` where range = "last_uid:*" (last synced UID to UIDNEXT-1)
        - Process returned headers (same upsert path as normal sweep)
        - Extract HIGHESTMODSEQ from SELECT response (need to capture it — async-imap select_condstore returns Mailbox with highest_modseq field)
        - Call `queries::set_highest_modseq(conn, mailbox, new_highest_modseq)`
        - Set a flag `condstore_fast_path = true` to skip the normal UID SEARCH ALL + header sweep (Steps 3-5)
     b. If select_condstore returns false OR condstore_fetch fails: log and fall through to normal path

3. UIDVALIDITY epoch guard (already exists at Step 3): when UIDVALIDITY changes, the existing wipe logic runs. ADD: also call `queries::set_highest_modseq(conn, mailbox, NULL)` to discard stored modseq. This ensures modseq is never trusted across epochs (per CONTEXT.md D-19, D-20, PITFALLS.md Pitfall 2).

4. Fallback path (CONDSTORE disabled OR highest_modseq NULL OR select_condstore false): normal UID SEARCH ALL + header sweep runs exactly as before (Phase 9 convergence shortcut still applies when UIDs unchanged).
