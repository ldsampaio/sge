## Observable-State Assertion Checklist (lifts into planner must_haves)

The live run drives the send pipeline through these `send_status` states and
asserts the existing UI surfaces reflect each one. STATE-first (IPC payload),
VISUAL-second (component renders). The planner lifts each row as an assertion;
the harness may assert via IPC payload + DOM query, no new test UI needed.

| # | Pipeline state (D-ref) | `send_status` IPC expectation | Existing UI assertion |
|---|------------------------|-------------------------------|----------------------|
| A-01 | Offline enqueue (D-09) | `pending_count ≥ 1`, `queued ≥ 1` | `OutboxBadgeWired` visible beside `SyncStatus` in `App.tsx:142` with `{N} mensagem(s) pendentes`; `SendStatus` shows pending line `{N} alteração(ões) aguardando envio` |
| A-02 | Flush / sending (D-09) | `sending ≥ 1` transiently, then `pending_count → 0` | Badge visible during flush, hidden (returns null, `visible=false`) once acked; no stuck badge after arrival |
| A-03 | Sent + acked (D-05/D-06) | `pending_count = 0`, `failed = 0`, `uncertain = 0` | Badge hidden; `SendStatus` shows neither pending line nor failed surface (clean state) |
| A-04 | `uncertain` after DATA-timeout fault (D-10) | `uncertain ≥ 1` | `SendStatus` uncertain line visible: "Reconciliando na pasta Enviadas — …" with `role="status"`; NO new send issued while uncertain (reconcile-not-resend is backend, UI shows the hold line) |
| A-05 | Crash mid-`sending` → restart (D-11) | `sending → queued` after `crash_recover`, then flushes to 0 exactly once | Badge reappears as pending (not failed) after restart, then clears on flush; failed surface MUST NOT appear for the crash-recovered item |
| A-06 | Failed → retry affordance (D-09/D-14) | `failed ≥ 1` | `SendStatus` failed surface visible: `{N} mensagem(ns) com falha` with `role="alert"` + per-row reason + `Retentar` button (`onRetry` wired); retry click requeues (badge returns to pending) |
| A-07 | `sent-unfiled` APPEND-retry path (D-07) | `sent_unfiled ≥ 1`, `failed = 0` for that item | MUST NOT render as a failed row and MUST NOT offer `Retentar`-as-resend; pending/ack indicator until APPEND retry succeeds (never a re-SMTP-send) |
| A-08 | Pending indicator until acked (general) | any `pending_count > 0` | `OutboxBadgeWired` + `SendStatus` pending line both present until server ack; both clear together (no split-brain) |
| A-09 | Test-mail identifiability (D-14) | n/a (harness audit) | No UI change; test rows carry the `SGE-TEST-` subject prefix so they are visually distinguishable in webmail during the run |

Out of scope for UI assertions (explicitly NOT visual, per CONTEXT.md): D-01/D-03
sandbox guards, D-04 keyring flow, D-08 server auto-save probe, D-12 oversize/BCC
doubles, D-13 secret scan, D-15 cleanup, D-16 draft-send transaction orphan check.
Those are harness/log/DB assertions, never UI.
