# Plan 12-03: Drafts UI — editor + Drafts folder + dirty-only autosave

## Overview

- **Goal:** The user can write a draft, save it explicitly, watch it autosave while dirty, resume editing it later from the Drafts folder, and discard it — all local-first with no network wait, reusing the message list for display.
- **Mode:** mvp
- **Type:** vertical (frontend over the frozen 12-02 command contract; full compose reply/forward/attachments UI stays Phase 14)
- **Deps:** Plan 12-01 (store shapes the row; no direct import). Runs parallel-safe with 12-02: disjoint files, command contract frozen below (identical text in both plans).
- **Requirements:** DRAFT-01 (full user-visible: save/edit/resume locally). DRAFT-02 (user-visible: exactly-one-copy needs no UI beyond the saved indicator).

**Frozen command contract (verbatim from 12-02):** `invoke("save_draft", { id, subject, body, to, cc, bcc, mailbox? })` → `DraftSaveResult { id, dirty: bool, server_uid: number | null, acked: boolean, pending_count: number }`; `invoke("get_draft", { id })` → full row `{ id, subject, body, to, cc, bcc, dirty, server_uid, message_id }`; `invoke("discard_draft", { id })` → `{ id, discarded: true }`; missing-Drafts error string starts with `"drafts-missing"`; `mailbox` defaults to the roles-resolved Drafts wire name.

## Wave 2b: Editor + Drafts view + autosave (disjoint files from 12-02)

Objective: draft editing works against the real commands (or the frozen contract), `tsc --noEmit` clean, no network wait on keystroke or save.

### Tasks

1. **`src/components/DraftEditor.tsx` (new) — editor form + explicit save/discard**
   - read_first: `src/components/ReadingPane.tsx` (message display + styling), `src/components/ExpungeModal.tsx` (confirm-dialog skeleton), `src/types.ts` (shared result/row shapes — add `DraftSaveResult` + `DraftRow` here).
   - Action: props `{ draftId: string | null (null = new, uuid via crypto.randomUUID), initial?: DraftRow, onSaved(DraftSaveResult), onDiscarded(id) }`. Fields To/Cc/Bcc (comma-separated text inputs), Subject, body `<textarea>`; dirty tracking on any keystroke (pristine vs edited). Save button → `invoke("save_draft", …)` → `onSaved`; invoke reject with `drafts-missing` → show inline "Pasta Rascunhos não encontrada — criar?" confirm → `invoke("create_folder", { leaf: "Drafts", parent: null })` (Phase 11 flow) → retry save once. Discard button → if dirty content exists, confirm via ExpungeModal skeleton ("Descartar rascunho?"), then `invoke("discard_draft", …)` → `onDiscarded`. Status line: "Salvando…" during invoke, "Salvo" when clean, "Não salvo — sem conexão" when `acked=false` (SyncStatus copy tone, pt-BR). `role="form"` + `aria-label`s on all inputs.
   - acceptance: typing marks dirty without any invoke call; Save invokes with all six fields + id; discard with pristine content skips confirm; `drafts-missing` triggers the create-then-retry path exactly once.
   - Verify: <automated>`tsc --noEmit`</automated>
   - <fails_when>non-zero exit, or any TS error naming `DraftEditor`</fails_when>

2. **Drafts view wiring — list reuse + open/resume + Novo rascunho**
   - read_first: `src/components/MailboxView.tsx` (selection + list wiring), `src/components/Sidebar.tsx` (`SYSTEM_ORDER`, Drafts display mapping "Rascunhos"), `src/components/MessageList.tsx` (row selection).

Selecting the Drafts folder ("Rascunhos") shows its messages via the existing `list_messages` path; clicking a draft row opens it in `DraftEditor` seeded by `invoke("get_draft", { id })` where the row id maps to the compose session (new drafts appear after first save; server-only copies with no local row use the rare server-fallback inside `get_draft`). "Novo rascunho" button at the top of the Drafts view opens a blank `DraftEditor` (`draftId=null` → fresh uuid on first save). After save, the list refreshes (existing refresh path) so the draft appears/updates without a full sync.
   - acceptance: Drafts folder selectable as "Rascunhos"; row click loads row content into the editor; new button opens blank editor; saved draft visible in the list after refresh.
   - Verify: <automated>`tsc --noEmit`</automated>
   - <fails_when>non-zero exit, or any TS error naming `MailboxView`/`MessageList`/`Sidebar`</fails_when>

3. **30 s dirty-only autosave tick + pending indicator**
   - read_first: `src/components/SyncStatus.tsx` (poll timer ~218, pending/error copy 244-260, `requestSync` entry), `src/components/DraftEditor.tsx` (task 1).
   - Action: `setInterval(30_000)` owned by the open `DraftEditor` (UI layer like the poll timer, not Tauri runtime — CONTEXT): on tick, if dirty AND not currently saving → same save path as the button (no-op otherwise — clean ticks never touch network or disk beyond the existing row). Clear on unmount/editor-switch. Indicator states follow SyncStatus tone: subtle "Salvo" (clean) vs "Salvando…" (in-flight) vs "Não salvo" (dirty/acked-false). Backend `pending_count` already includes dirty drafts (12-02), so SyncStatus pending reflects unsaved drafts with no frontend change beyond tone.
   - acceptance: clean tick → zero invoke calls (assert via invoke mock/spy or network-call count in dev); dirty tick → exactly one `save_draft`; unmount clears the interval (no tick after close); indicator shows the three states.
   - Verify: <automated>`tsc --noEmit`</automated>
   - <fails_when>non-zero exit, or any TS error naming the touched files</fails_when>

## <threat_model>

- **Scope:** ASVS L1. Display + form; no new transport.
- **Hazards:**
  - T-12-06 *Draft content rendered as HTML (XSS from another client's draft):* the editor shows body in a `<textarea>` (never `dangerouslySetInnerHTML`); the reading view of Drafts-folder messages reuses the existing sanitized ReadingPane path (ammonia + sandboxed iframe). Block on high: any HTML injection of draft body.
  - T-12-07 *Autosave storm (a tick per keystroke or per editor instance):* single interval per open editor, dirty-gated, in-flight-guarded. Block on high: overlapping concurrent `save_draft` invokes from one editor.
- **Block on high:** unsanitized draft-body HTML, or concurrent autosave invokes.
</threat_model>
