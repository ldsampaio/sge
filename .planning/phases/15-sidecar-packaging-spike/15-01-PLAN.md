# Plan 15-01: Sidecar freeze toolchain (laya[serve] → PyInstaller binary)

**Goal:** Reproducible script that builds `sge-laya-<target-triple>` from `laya[serve]==0.4.2` (CPU-only torch) and records the pinned checkpoint revision + sha256. Proves the Python server boots and answers `/health` (and documents the `/v1/systemone` shape for Phase 17).

**Tasks:**
1. `sidecar/requirements.txt` — pin `laya[serve]==0.4.2`, PyInstaller ~6.x, CPU-only torch index.
2. `sidecar/build-sidecar.sh` — `uv venv` → install → `laya-serve --help` smoke → PyInstaller one-file freeze → output `dist/sge-laya-<triple>`; writes `sidecar/pins.json` (laya version, checkpoint revision hash, sha256).
3. Boot the unfrozen `laya-serve` on loopback, `GET /health` → 200; record response shape + startup seconds in pins/notes.
4. Resolve checkpoint revision: multilingual checkpoint Hub revision hash for `LAYA_MAX_LOADED=1` preload; record in `pins.json`.
5. Document `/v1/systemone` request/response shape from installed 0.4.2 source (for Phase 17 bridge) in `sidecar/CONTRACT.md` — read-only docs, no call.

**Verification:**
- `bash sidecar/build-sidecar.sh` completes; `dist/sge-laya-<triple> --help` (or `/health` after boot) works.
- Frozen binary boots with NO network (offline env test: `unshare -n` or env with HF offline) and `/health` → 200.
- `sidecar/pins.json` has laya version + checkpoint revision + sha256.

**Does NOT do:** Tauri wiring, Rust supervision, classification calls (Phase 17).
