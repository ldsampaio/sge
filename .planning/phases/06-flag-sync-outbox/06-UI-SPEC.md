## Color

Source: `src/styles/tokens.css` semantic layer (pre-populated from codebase):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f4f5fd` (`--color-background`) | App background, pane surfaces |
| Secondary (30%) | `#ffffff` (`--color-card`) | Cards, message rows, sidebar, reader pane |
| Accent (10%) | `#4f46e5` (`--color-primary`, indigo-600) | Interactive emphasis only (see reserved list) |
| Destructive | `#dc2626` (`--color-destructive`) | Destructive actions only — unused in this phase (no delete/expunge per scope guard); error text in SyncStatus may use it |

Accent reserved for: unread dot (`--badge-unread-bg` amber `#ea580c` stays for the unread dot itself — see note), active/selected message row outline, primary "Buscar mensagens" button, pending-sync row marker, focus ring (`--color-ring`). Never for body text or decorative illustration.

Notes:
- Unread-dot color stays amber `#ea580c` (`--badge-unread-bg`) — existing triage signal, unchanged by this phase. Accent indigo is reserved for the items above.
- Pending (unacknowledged toggle) state uses `--color-accent-soft` `#ffedd5` row wash + existing `.sync-progress` treatment — subtle, never blocks browsing (locked CONTEXT.md decision).
- Text: `--color-foreground` `#1e1b4b` on light surfaces; muted `--color-muted-foreground` `#475569`; borders `--color-border` `#c7d2fe`. All pairs hold WCAG AA per tokens.css header claim.
- Success confirmation (server-acknowledged toggle) uses existing `--color-success` `#15803d` only in SyncStatus text, never as a row wash.

## Copywriting Contract

App language is pt-BR (existing UI strings). All copy below is pt-BR:

| Element | Copy |
|---------|------|
| Primary CTA | Buscar mensagens (existing SyncStatus button — unchanged; flag toggles are icon/dot affordances, not CTAs) |
| Flag toggle (list) | Clickable unread dot, `aria-label` "Não lido" / "Lido" (existing pattern in `MessageList.tsx:211-214`); clicking toggles read/unread optimistically |
| Flag toggle (reader) | Marcar como lido / Marcar como não lido (reader header button, label reflects target state) |
| Seen-on-open behavior | Opening a message marks it read automatically (Thunderbird-style Seen-on-open, locked CONTEXT.md decision); no confirmation, no toast — row updates optimistically |
| Pending indicator (row) | Subtle `--color-accent-soft` row wash while toggle is unacknowledged; dot keeps target state. No text on the row itself |
| Pending indicator (aggregate) | SyncStatus line: "3 alterações aguardando envio" (count + noun; hidden when zero) |
| Empty state heading | Sua fila de leitura está vazia (existing `MessageList.tsx` copy — unchanged) |
| Empty state body | Busque os avisos com o botão "Buscar avisos" acima. Depois da primeira busca, tudo fica guardado para estudar offline. (existing — unchanged) |
| Error state | Falha na busca: {detail} + button "Tentar de novo" (existing `SyncStatus.tsx` pattern). Flag-replay failures surface here as: "Não foi possível enviar N alteração(ões) de leitura — tentando de novo na próxima busca." Retry is automatic on next sync; no manual flush button (locked CONTEXT.md decision) |
| Offline queued state | Offline · alterações guardadas — serão enviadas ao reconectar (shown in SyncStatus when outbox is non-empty and session is down) |
| Destructive confirmation | none — this phase has no destructive actions (no delete/expunge/move per scope guard; read/unread toggles are reversible and need no confirmation) |

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|

| loading | flag STORE round-trip | 🧪 backstop | Optimistic toggle applies instantly so no spinner is expected; held-out visual check that no loading skeleton appears on dot click |
