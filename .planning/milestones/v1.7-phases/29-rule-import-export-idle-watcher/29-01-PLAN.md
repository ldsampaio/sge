## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29-01 | Tampering | rules_io import validation | high | mitigate | Strict schema validation before DB write: reject empty patterns, reserved names, duplicate names, priority range, dest_kind enum; no raw SQL, only parameterized queries via rusqlite |
| T-29-02 | Denial of Service | rules_io export/import | low | accept | JSON size bounded by folder_rules row count (user-controlled, max ~1000 rules); no streaming parse needed |
| T-29-03 | Information Disclosure | export_rules command | low | mitigate | Export only contains rule metadata (no message content, no credentials); redaction sanitizer from Phase 16 not needed here but reuse pattern if extended |
| T-29-04 | Elevation of Privilege | import_rules command | medium | mitigate | Command requires Tauri capability (already gated); validation runs before any DB mutation; rule_id is UUID not user-controlled integer |
| T-29-SC | Tampering | npm/pip/cargo installs | high | mitigate | package-legitimacy gate + blocking human checkpoint for [ASSUMED]/[SUS] — no new deps in this plan (async-imap 0.11.3, serde, uuid, chrono already pinned) |
