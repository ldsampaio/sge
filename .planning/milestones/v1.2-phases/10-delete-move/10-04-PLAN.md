## <threat_model>

- **Scope:** ASVS L1. UI is the last guard before irreversible server ops — confirmation and scoping live here.
- **Hazards:**
  - *One-click permanent loss (no confirm):* mitigated by ExpungeModal always preceding `expunge_messages`; delete path always targets Trash first, never expunge. Cancel is default-focused, never the destructive button.
  - *Wrong-folder expunge from stale selection:* modal names folder + count from live selection; command sends only selected UIDs (`uid_expunge` set), never bare `expunge()`.
  - *Destructive button mis-tap (color-only distinction):* trash glyph + "para sempre"/"Não dá para desfazer" text accompany red styling per UI-SPEC.
  - *Undo-after-sync (reverse op against changed epoch):* Desfazer valid iff op still in `imap_outbox`; toast dies when next sync starts; backend epoch-drop is the backstop.
  - *Display-name vs wire-name confusion (move to wrong folder / CREATE twin-trash):* UI passes raw `name`; Trash CREATE behind confirm only.
- **Block on high:** any `expunge_messages` invoke outside the modal confirm path, any bare-folder expunge from UI, or undo path that bypasses the still-queued check → block.
</threat_model>
