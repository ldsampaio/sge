# Plan 12-01: Drafts foundation — M9 store + RFC 5322 renderer + APPEND transport

## Overview

- **Goal:** Draft persistence foundation is proven without network: the `drafts` table stores compose sessions, raw RFC 5322 bytes render correctly (mail-parser round-trip), and the APPEND + Message-ID SEARCH transport verbs work through the session with tests.
- **Mode:** mvp
- **Type:** tracer (backend vertical — proves store → render → APPEND → reconcile against fakes; the user-visible save/edit path completes in Plans 12-02/12-03)
- **Deps:** Phase 11 complete (`Role::Drafts` resolution, M8 migration pattern, `create_trash` lease shape). No intra-phase deps (first wave).
- **Requirements:** DRAFT-01 (local backing store + renderer this plan; editing UI in 12-03), DRAFT-02 (transport verbs this plan; server persist sequence in 12-02).

## <threat_model>

- **Scope:** ASVS L1. No network, no user input reaches the wire in this plan (renderer output is stored/tested only).
- **Hazards:**
  - T-12-01 *Migration data loss:* mitigated by forward-only M9 + preserve-rows test copied from the M7 template. Block on high: any `ALTER`/`DROP` touching pre-M9 tables.
  - T-12-02 *Header injection via subject/recipient newlines:* renderer must strip/encode CR/LF in header fields (encoded-word or reject) — test with `"Subject\r\nBcc: evil"` asserting no second header survives the round-trip. Block on high: raw newline reaching emitted headers.
- **Block on high:** destructive migration, or header-injection bytes in renderer output.
</threat_model>
