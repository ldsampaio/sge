## Wave 3: Roles + UI + hardening (blocked on 11-02)

Objective: everything the user touches, plus the bookkeeping that makes guards role-aware instead of name-guessing.

### Tasks

1. **`src-tauri/src/store/mod.rs` + `queries.rs` — M8 roles/attributes bookkeeping**
   - `SCHEMA_VERSION` 7 → 8; `M8_ROLES_SQL`: `ALTER TABLE mailboxes ADD COLUMN role TEXT NOT NULL DEFAULT '';` + `ADD COLUMN attributes TEXT NOT NULL DEFAULT '';` forward-only. `set_mailbox_role(conn, name, role, attributes)` upsert helper; extend `list_mailboxes` SELECT + `MailboxRow` with `role`/`attributes`; extend frontend `MailboxRow` (`src/types.ts`) with the same two string fields.
   - Preserve-rows test mirroring `m2_upgrades_v1_database_forward_preserving_rows`: v7 DB with rows + delimiter values upgrades to v8 with data intact and `role`/`attributes` defaulted.
   - Verify: <automated>`cargo test -p sge store::`</automated>
   - <fails_when>non-zero exit, or the preserve-rows test FAILED / data mismatch</fails_when>

2. **`src-tauri/src/imap/roles.rs` (new) — role resolution generalizing `trash.rs`**
   - `pub enum Role { Inbox, Trash, Sent, Drafts, Custom }` + `pub fn resolve_roles(mailboxes: &[MailboxInfo]) -> Vec<(String, Role)>`: layer order SPECIAL-USE attribute → full-name match → leaf match (same order as `detect_trash`); INBOX matched first by case-insensitive name; `\Noselect` rows resolve `Custom` and are never role targets; first hit wins per mailbox.
   - Name lists: move `TRASH_FULL/LEAF_NAMES` here (not copied); add SENT (`sent`, `sent messages`, `enviadas`, `enviados`, `[gmail]/sent mail`) and DRAFTS (`drafts`, `rascunhos`, `[gmail]/drafts`) lists mirroring Sidebar `SYSTEM_ORDER` ranks 1-2.
   - `detect_trash` in `trash.rs` becomes a delegating wrapper (find `Trash` entry → `Found`, else `Missing`); its 8 existing tests must pass UNCHANGED — that is the no-second-detector proof (RESEARCH §9).
   - Wire into the `list_mailboxes` refresh: after each folder's STATUS, `set_mailbox_role` with the resolved role + space-joined attributes.
   - Tests: attribute-wins-over-name for `\Sent`/`\Drafts`; Gmail-style; leaf match; `\Noselect` never targeted; INBOX never Trash; `detect_trash` delegation parity (same fixtures, same results).
   - Verify: <automated>`cargo test -p sge imap::trash:: imap::roles::`</automated>
   - <fails_when>non-zero exit, or any delegation parity mismatch</fails_when>

3. **`src/components/` — context menu + delete modal + selection wiring**
   - `FolderContextMenu.tsx` (new): `role="menu"`, items Renomear / Excluir pasta with `aria-label`s per UI-SPEC; disabled states with tooltips: INBOX (both ops), system-role rows (`role` ∈ trash/sent/drafts — rename disabled, "{papel} do sistema…" tooltip), `\Noselect` (both hidden — filtered, not just disabled); keyboard: arrows/Enter/Esc, focus return.
   - `FolderDeleteModal.tsx` (new): copies `ExpungeModal.tsx` skeleton (portal, `alertdialog`, focus-Cancel-default, Esc/backdrop-cancel, trap + return); empty-folder copy vs non-empty copy + typed-name input (confirm disabled until exact display-name match) per UI-SPEC table; `need_delete_confirm:{count}` from the command drives the non-empty variant.
   - `Sidebar.tsx`: right-click + keyboard opening of the menu per item; `buildTree` already exported (11-01); system rows show role glyph treatment only (no behavior change to ordering).
   - `MailboxView.tsx`: rename success → `setSelectedMailbox(new)` in the same tick as the tree refresh (atomic, CONTEXT locked); delete success → `setSelectedMailbox("INBOX")`; `./FolderDialog` rename mode (input pre-filled with leaf segment, no parent picker).
   - Trash-missing confirm path reuses the existing `need_trash_confirm` flow untouched (one-time CREATE behind confirmation, never silent).
   - Verify: <automated>`tsc --noEmit`</automated>
   - <fails_when>non-zero exit, or any TS error in the new/modified components</fails_when>

## <threat_model>

- **Scope:** ASVS L1. Role-aware guards are the last line before destructive verbs; UI is the only caller.
- **Hazards:**
  - T-11-07 *Role/attribute drift (stale `role` column says Custom for Trash → rename offered on Trash):* mitigated by recompute-on-every-LIST-refresh (column is a cache, LIST is truth) + disabled-state double-guard in the command. Block on high: any guard reading role without a refresh path writing it.
  - T-11-08 *Second Trash detector drifting from the first:* mitigated by delegation (one code path, parity tests); `trash.rs` name lists MOVED not copied. Block on high: a new name-match list that duplicates `TRASH_*` constants.
  - T-11-09 *Destructive-by-default UI (Enter confirming delete, INBOX offered):* mitigated by Cancel-default-focus, typed-confirm gate, INBOX/`\Noselect` never offered; destructive never color-alone. Block on high: confirm button default-focused, or a menu path reaching `delete_folder("INBOX")`.
- **Block on high:** stale-role guards, duplicated Trash lists, destructive-default UI, NAMESPACE sent → block.
</threat_model>
