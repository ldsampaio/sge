# Plan 04-03 — Security hardening: CSP + sandbox verification

## Objective

Verify and harden the end-to-end message rendering pipeline against XSS and
IPC-leakage threats. This is a security verification wave, not a feature wave.

## Context

- Phase 3's `sanitize_html` test already proves ammonia strips `<script>` and `<iframe>`.
- The `bodies.rs::sanitize_html` uses `ammonia::Builder::new()` (default allow-list).
- T-04-03 (Malicious mail): script/srcdoc/object payloads must render inert with
  no Tauri IPC reachability.
- Need: CSP meta-tag in the iframe document, sandbox attribute, and a proof
  that `window.__TAURI__` is not accessible from the iframe.

## Tasks

<task id="t1-csp">
  <name>Add CSP meta-tag + sandbox to ReadingPane iframe</name>
  <acceptance>
    - iframe has `sandbox="allow-same-origin"` (no allow-scripts, no allow-forms, no allow-popups)
    - iframe document includes `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; img-src 'self'; style-src 'unsafe-inline'; ...">`
    - Remote images blocked (img-src 'self' or data: only)
    - No inline scripts (script-src 'none')
  </acceptance>
  <action>Embed CSP meta-tag in the iframe's HTML document (srcDoc construction)</action>
