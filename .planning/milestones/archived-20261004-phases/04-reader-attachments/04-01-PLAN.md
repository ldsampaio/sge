# Plan 04-01 — fetch_message + save_attachment Tauri commands

## Objective

Create two Tauri commands that fetch a single message body from IMAP (on-demand,
peek-only) and return sanitized content + attachment metadata to the frontend.
Also: save attachment files to disk via a user-chosen path.

## Context

- `bodies.rs` already has `sanitize_html()` and `fetch_body_message()`. Must
  add `pub mod bodies;` to `sync/mod.rs`, extend `fetch_body_message` to also
  extract attachment metadata, and add a `fetch_message_detail` wrapper.
- `fetch_body_message` currently takes `&mut dyn SyncSession`. The Tauri command
  creates the session via `connect_sync` (same pattern as `start_sync`).
- Need `MessageView` + `AttachmentInfo` serializable structs.
- Need `save_attachment` that re-fetches body, extracts the part, and writes to disk.

## Threat Model

- T-02-03: BODY.PEEk[] only — never `BODY[]` (never sets \Seen)
- T-02-04: 30s read timeout inherited from session core
- T-04-01: Attachment filenames reduced to basename — no `../../etc/passwd` traversal
- T-04-02: Attachment path is user-supplied from a native save dialog — not untrusted input
