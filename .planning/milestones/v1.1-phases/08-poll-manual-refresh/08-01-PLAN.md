## Wave 1 — Poll infrastructure (08-01-PLAN.md)

### Objective
Establish the poll timer infrastructure with single-flight guard so periodic refreshes never overlap.

### Tasks

**Task 1 — Single-flight guard** (`src-tauri/src/sync/worker.rs`):
- Add `EXECUTING` flag (AtomicBool) to sync worker
- Guard: fire poll timer only when `!EXECUTING`; set on sync start, clear on sync completion
- Return early from poll callback if already executing

**Task 2 — Poll timer** (`src-tauri/src/lib.rs` / `src/main.rs`):
- Add `setInterval`/`set_timeout` using Tauri'\''s async runtime
- Default interval: 5 minutes (configurable via env / tauri config)
- On tick: invoke `start_sync()` with no mailbox parameter (defaults to INBOX for v1.1)
- Emit `SyncEvent::Poll` on timer fire

**Task 3 — Manual refresh** (`src/components/SyncStatus.tsx`):
- Add "Get Mail" button that invokes `start_sync()` through the same code path as the poll timer
- Disable button if single-flight flag is set (prevent overlapping syncs)
- Show honest "reconnecting…" state when session expires, and sync resumes after keyring re-read + re-SELECT

*As-built 2026-10-05: guard is `SyncGate` in `sync/mod.rs` (RAII `SyncGuard`,
Drop releases) held on `AppState`; `start_sync` skips with `Ok` when busy.
The timer lives in `SyncStatus.tsx` (`POLL_INTERVAL_MS = 5 min`) and shares
one `requestSync` entry with the manual button — one code path under the
same backend guard. No `SyncEvent::Poll` variant: busy ticks skip silently.
Reconnecting state + one auto-retry live in `SyncStatus`; resume reuses the
existing keyring fallback + re-SELECT in `start_sync`.*
