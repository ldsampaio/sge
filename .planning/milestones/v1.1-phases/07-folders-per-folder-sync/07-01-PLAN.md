# Phase 7 Plan — Folders + Per-Folder Sync

## Overview

**Goal**: User can browse every mailbox, not just INBOX, with per-folder unread triage signals.

**Mode**: mvp  
**Depends on**: Phase 6 (complete)  
**Requirements**: FOLD-01, FOLD-02, FOLD-03  

**Build order**: Backend trait extension → Commands + DB migration → Frontend folder tree.

---

## Wave 1 — Backend: SyncSession + SyncWorker multi-folder (07-01-PLAN.md)

### Objective
Generalize the INBOX-only sync infrastructure to support arbitrary mailboxes.

### Tasks

**Task 1 — Extend SyncSession trait** (`src-tauri/src/imap/mod.rs`)
- Add `select_mailbox(&mut self, name: &str) -> PinBox<'_, Result<MailboxSummary, SyncError>>` — SELECT any mailbox by name
- Add `list_mailboxes(&mut self) -> PinBox<'_, Result<Vec<MailboxInfo>, SyncError>>` — LIST "" "*" to discover folders
- Add `MailboxInfo` struct: `{ name: String, delimiter: String, attributes: Vec<String> }`
- Implement both on `BoxedSession` using async-imap's `self.select(name)` and `self.list("", "*")`
- Keep `select_inbox()` as a convenience that calls `select_mailbox("INBOX")`

**Task 2 — Generalize SyncWorker** (`src-tauri/src/sync/worker.rs`)
- Change `sync_with_session` signature to accept `mailbox_name: &str` (default "INBOX")
- Replace hardcoded `"INBOX"` in ensure_mailbox, get_sync_state, set_sync_state with `mailbox_name`
- Replace `session.select_inbox()` with `session.select_mailbox(mailbox_name)`
- Add `SyncMailbox` method on SyncWorker that wraps session creation + sync for a specific folder

**Task 3 — Extend SessionManager** (`src-tauri/src/imap/manager.rs`)
- Add `select_mailbox(&self, name: &str)` that leases the session + SELECTs the named mailbox
- Add `list_mailboxes(&self)` that leases, runs LIST, returns Vec<MailboxInfo>
- Keep `set_seen` working through the INBOX-lease (no change needed — set_seen already uses the leased session)

### Verification
```
cargo test --manifest-path src-tauri/Cargo.toml sync_worker_mailbox
```

## Wave 2 — Commands + DB Migration (07-02-PLAN.md)

### Objective
Expose multi-folder sync to the Tauri command layer with per-folder STATUS caching.

### Tasks

**Task 1 — DB Migration M3** (`src-tauri/src/store/mod.rs`)
- Add `unseen_count INTEGER DEFAULT 0` column to `mailboxes` table via M3 migration
- Update `SCHEMA_VERSION` to 3
- Write migration test: `m3_adds_unseen_count_column`

**Task 2 — Query functions** (`src-tauri/src/store/queries.rs`)
- Add `list_mailboxes(conn) -> Vec<MailboxRow>` — returns all folders with unread counts
- Add `MailboxRow` struct: `MailboxRow { id: u64, name: String, uid_validity: u32, uid_next: u32, unseen_count: i64, last_sync_at: Option<String> }`
- Add `set_mailbox_status(conn, name, uid_validity, uid_next, unseen_count)` — upsert STATUS data
- Add `count_unread(conn, mailbox_id) -> i64` — count messages with flags not containing \Seen

**Task 3 — Tauri commands** (`src-tauri/src/commands/sync.rs`)
- Add `list_folders(state) -> Result<Vec<MailboxRow>, String>` — calls SessionManager.list_mailboxes + STATUS, caches in DB, returns rows
- Generalize `start_sync(state, mailbox: String, on_event)` — accept mailbox name, SELECT that folder
- Generalize `sync_status(state, mailbox: String)` — look up sync state for the named mailbox
- Generalize `list_messages(state, mailbox: String, offset, limit)` — filter by named mailbox
- Generalize `fetch_message(state, uid, mailbox: String)` — SELECT the named mailbox before fetch

### Verification
```
cargo test --manifest-path src-tauri/Cargo.toml sync_command_mailbox
cargo test --manifest-path src-tauri/Cargo.toml m3
```

## Wave 3 — Frontend folder tree (07-03-PLAN.md)

### Objective
Show the real server folder tree in the sidebar with unread badges; browse any folder.

### Tasks

**Task 1 — Types** (`src/types.ts`)
- Add `MailboxRow` interface: `{ id, name, uid_validity, uid_next, unseen_count, last_sync_at }`
- Rename existing `MessageRow` import if needed

**Task 2 — Sidebar** (`src/components/Sidebar.tsx`)
- Replace hardcoded fake entries with dynamic rendering from `folders: MailboxRow[]` prop
- Show unread count badge per folder (sourced from STATUS/UNSEEN)
- Render separator between INBOX and other folders
- Highlight selected folder

**Task 3 — MailboxView** (`src/components/MailboxView.tsx`)
- Wire `handleMailboxSelect` to call `onMailboxSelect(m)` (currently a no-op)
- Pass selected mailbox to MessageList, SyncStatus, sync/list commands

**Task 4 — App.tsx**
- Add `selectedMailbox` state, initialized to "INBOX"
- Call `list_folders` on connect, store result
- Pass `selectedMailbox` + `onMailboxSelect` to MailboxView
- Pass folder data to Sidebar for rendering

| Constraint | How satisfied |
|-----------|--------------|

| UIDVALIDITY-guarded per folder | `sync_with_session` checks UIDVALIDITY per `mailbox_id` |
| Credentials in keyring only | No change — reuses Phase 5 auth |
| Linux-only bundle | No change |
