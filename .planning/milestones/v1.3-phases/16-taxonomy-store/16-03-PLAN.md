# Plan 16-03: Redaction sanitizer (input + output)

**Goal:** `classify/redact.rs` — the ONE sanitizer every later phase reuses.
No secret ever lands in the DB, logs, or justifications.

**Tasks:**
1. `redact_input(&str) -> String`: scrubs senhas (`senha|password|passwd`
   + value), códigos (`código|codigo|token|otp|verificação` + value,
   standalone 4–8 digit codes), CPF (`\d{3}\.\d{3}\.\d{3}-\d{2}` + bare
   11-digit), RA/matrícula (`\b(ra|matrícula)\s*\d+`), telefone BR,
   `api[_-]?key|secret|bearer` values. Replacement `[REDACTED:<kind>]`.
   No `regex` crate? check lock — else hand-rolled scanning (diacritic-fold
   first). Prefer adding `regex = "1"` only if absent from lock (offline).
2. `filter_output(&str) -> String`: second-pass backstop with the same
   patterns + a paranoid digit-run rule (any 6+ digit run → redact) for
   justification text.
3. Fixture tests (≥8): password-reset mail (senha temporária + código),
   boleto (código de barras run), CPF-in-signature, token URL, matrícula;
   assert ZERO secret substrings survive either pass; assert kinds preserved
   (`[REDACTED:code]` still signals "a code exists").
4. Doc comment: theOREM — every later phase MUST route evidence through
   `redact_input` and justifications through `filter_output`; labels store
   IDs only (enforced by schema, not convention).

**Verification:** `cargo test classify::redact` green; adversarial fixtures
(all secrets from STATE.md "password-reset email" scenario) clean.
