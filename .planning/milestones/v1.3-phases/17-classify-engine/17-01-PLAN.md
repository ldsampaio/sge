# Plan 17-01: Bridge + worker + queue drain

**Goal:** Rust talks to the sidecar (`/v1/systemone`) behind sync with a
durable queue; sidecar down ⇒ `pending`, sync unaffected.

**Tasks:**
1. `classify/bridge.rs`: single-flight client (tokio Mutex), 10 s timeout,
   Bearer header, `choice`-top-level request builder (5 options from
   `top_level()`), response parser (choice/confidence/`x_jev_confidence`,
   runner-up extraction), typed errors (Timeout/Down/Refused/Parse — plain
   language, no key). Unit tests with mock HTTP server (axum? prefer
   `wiremock` only if cached — else raw TcpListener stub).
2. `classify/evidence.rs`: quote-strip → signal-extract → budget-fit
   (subject ≤200, snippet ≤1000); `redact_input` last step before return;
   `looks_clean` assert in debug. Fixture tests (thread with quotes,
   password-reset → clean).
3. `classify/worker.rs`: `ClassifyGate`, drain loop (dequeue N pending →
   bridge → upsert label → event), crash-safe (processing → pending on boot),
   UIDVALIDITY epoch check (drop stale rows), backoff on 500.
4. M13 migration: `classify_excluded_folders` + seed Sent/Drafts + optional
   watermark table (planner's pick) + preserve-rows test.
5. Post-sync hook in `sync/worker.rs` (enqueue new UIDs, skip excluded,
   fire-and-forget) + `classify_status` command.

**Verification:** `cargo test classify` green; mock-server tests prove
down→pending + retry; hook test proves sync completes with sidecar absent.
